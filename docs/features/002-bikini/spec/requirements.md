# bikini（仮称）: カスタム期間（16日〜翌月15日サイクル）カテゴリ別支出確認 要件定義書

## 1. 背景・課題

現在、本アプリの集計はすべて暦月（1日〜末日）単位に固定されている（ダッシュボードの当月合計、カレンダーの月次表示、予算タブの当月消化状況）。しかし、給与支給日やクレジットカードの締め日を基準に家計を管理しているユーザーにとって、実際の「家計のひと月」は暦月と一致しない。そのため「16日〜翌月15日」というサイクルでの支出をカテゴリごとに確認したいという要望がある。

※ 当初の要望では「収支」と表現されていたが、ユーザーによる訂正で**支出のみ**がスコープであることが確認済み（ideas.md 参照）。

## 2. 対象ユーザー

- 給与支給日・カード請求サイクル（16日〜翌月15日）を基準に家計を管理している本アプリの利用者
- 個人ノート利用者、およびパートナーと共有ノートを利用しているペアの両方

## 3. ゴール（成功条件）

**一文で**: 予算タブで「16日〜翌月15日」サイクルのカスタム期間（月度）に切り替えて、支出カテゴリごとの支出額と予算消化状況を確認できるようにする。

- [ ] ユーザーは予算タブの操作のみで、今日が属する月度（今日が1日〜15日なら前月16日〜今月15日、16日〜末日なら今月16日〜翌月15日）の支出カテゴリ別支出額を表示できる
- [ ] カスタム期間表示でも、各カテゴリの月次予算（totalBudget）を「その期間の予算」として消化状況を対比表示できる
- [ ] 暦月（1日〜末日）での予算表示も引き続き可能であり、両期間を切り替えられる
- [ ] 期間の境界が正しい（表示中の「N月度」に対して、N-1月16日 00:00:00 以降、N月16日 00:00:00 未満のレコードのみが集計対象）
- [ ] 個人ノート・共有ノートのどちらを選択していても同様に機能する

## 4. Non-goals（やらないこと）

- 収入カテゴリ別の集計表示（本機能は支出のみが対象。振替（transfer）も対象外）
- 任意の締め日設定（例: 25日締め）。期間の境界日は「16日」にハードコードで固定する【論点1: 判断A】
- 新規画面・新規タブの追加（既存の予算タブの拡張として提供する）【論点2: 判断B】
- 予算（totalBudget）の日割り按分（カスタム期間でも totalBudget をそのまま「1期間分の予算」として扱う）【論点3: 判断B】
- 週単位・年単位など、16日〜15日以外の新たな集計期間の追加
- 集計結果のエクスポート（CSV等）や通知機能
- 過去データの移行・変換（既存レコードは日付を持つため、集計方法の追加のみで対応可能）
- レコード入力・編集機能の変更（確認（Read）機能のみが対象）

## 5. 用語定義

| 用語 | 定義 |
|------|------|
| 暦月期間 | 当月1日 00:00:00 から翌月1日 00:00:00 未満までの期間（半開区間） |
| カスタム期間（N月度） | 前月16日 00:00:00 から当月16日 00:00:00 未満までの期間（半開区間）。当月に紐づけて「N月度」と呼ぶ（例: 「7月度」= 6月16日〜7月15日） |
| 今日が属する月度 | 今日の日付が1日〜15日なら当月度、16日〜末日なら翌月度（例: 7月5日→7月度、7月20日→8月度） |
| カテゴリ別支出 | 支出カテゴリごとの支出合計金額 |
| 予算消化状況 | 支出カテゴリの totalBudget に対する期間内支出合計の割合・対比表示（現行予算タブの表示形式） |
| ノート | 家計簿データの単位。個人ノート（personalNotes）と共有ノート（sharedNotes）がある |

## 6. 機能要件（FR）

- FR-001: As a 家計簿ユーザー, I want to 予算タブでカスタム期間（月度）における支出カテゴリごとの支出額と予算消化状況を確認する, so that 給与・カード請求サイクルに合わせて支出と予算の実態を把握できる
- FR-002: As a 家計簿ユーザー, I want to 予算タブで暦月期間とカスタム期間の表示を切り替える, so that 用途に応じた期間軸で同じカテゴリ別支出を見比べられる
- FR-003: As a 家計簿ユーザー, I want to 過去のカスタム期間（先月度、先々月度…）に遡って確認する, so that 期間ごとの支出の推移を振り返られる
- FR-004: As a 共有ノート利用者, I want to 共有ノートに対してもカスタム期間のカテゴリ別支出を確認する, so that パートナーとの共同家計も同じサイクルで把握できる

## 7. 非機能要件（NFR）

### 性能

- NFR-001: カテゴリ別支出の表示は、通常のデータ量（1期間あたりレコード数百件程度）において、既存の予算タブ（暦月表示）と同等の体感速度で表示されること

### セキュリティ

- NFR-002: 集計対象データへのアクセスは既存の Firestore セキュリティルールの範囲内であること（個人ノートは所有者のみ、共有ノートは owners のみ）。本機能のために新たな読み取り権限を追加しないこと

### 可用性・信頼性

- NFR-003: データ取得に失敗した場合、既存画面と同様にエラー表示を行い、アプリがクラッシュしないこと

## 8. 制約

- 技術スタック: Flutter + Firebase（Firestore）。既存の Clean Architecture（Repository / Service 分離、Command パターン）に従う
- 新規コードは v2 アーキテクチャ（`lib/v2/`）の規約（Provider による DI、Either によるエラーハンドリング、freezed による VO/Entity）に従う
- レコードの `date` フィールドは既存スキーマのまま変更しない（集計クエリの範囲指定のみで実現する）
- 既存の暦月表示の挙動を変えない（後方互換）
- **期間指定でのデータ取得は、既存の暦月固定メソッド（Repository の `fetchMonthly` / Service の `fetchByDate(uid, year, month)`）を期間指定を受け取る形に一般化して対応する**（新メソッドの追加ではなく既存メソッドの一般化）【TQ-001: 決定済み】
- **カテゴリ別集計は現行の予算タブと同様にクライアント側で行う**（Firestore の集計クエリは使用しない）【TQ-002: 決定済み】
- **「暦月期間」と「カスタム期間」はそれぞれ独立した値オブジェクトとして定義し、両者に共通する抽象（抽象クラスまたはインターフェース）を設けて、一般化されたデータ取得メソッドはその抽象を受け取る**【TQ-003: 方針決定済み、詳細は設計フェーズ】

## 9. 受け入れ基準（AC）

### FR-001 に対する受け入れ基準

#### AC-001: カスタム期間のカテゴリ別支出と予算消化状況が表示される（正常系）

- **Given** 個人ノートの支出カテゴリ「食費」（予算30,000円）に 6月16日、7月1日、7月15日 の支出レコード（各1,000円）が存在し、今日が7月10日である
- **When** ユーザーが予算タブでカスタム期間表示に切り替える
- **Then** 「7月度」（6月16日〜7月15日）として「食費」の支出合計3,000円と、予算30,000円に対する消化状況が表示される

#### AC-002: 期間境界外のレコードは集計されない（境界条件）

- **Given** 6月15日 と 7月16日 の支出レコードが存在する
- **When** ユーザーが「7月度」（6月16日〜7月15日）のカテゴリ別支出を表示する
- **Then** どちらのレコードも集計に含まれない（6月15日のレコードは「6月度」に、7月16日のレコードは「8月度」に含まれる）

#### AC-003: 期間内にレコードが1件もない（境界条件）

- **Given** 対象期間内に支出レコードが存在しない
- **When** ユーザーがカスタム期間のカテゴリ別支出を表示する
- **Then** 各カテゴリの支出が0円として表示される（エラーにならない）

#### AC-004: データ取得に失敗する（異常系）

- **Given** ネットワーク断などにより Firestore からのデータ取得が失敗する状態である
- **When** ユーザーがカスタム期間のカテゴリ別支出を表示する
- **Then** エラーが発生した旨が表示され、アプリはクラッシュしない

#### AC-005: レコードを持たないカテゴリも表示される（境界条件）

- **Given** 支出カテゴリ「趣味」が存在するが、対象期間内に「趣味」の支出レコードが存在しない
- **When** ユーザーがカスタム期間のカテゴリ別支出を表示する
- **Then** 「趣味」が支出0円として一覧に表示される

### FR-002 に対する受け入れ基準

#### AC-006: 今日が月の前半のとき、切り替えると当月度が表示される（正常系）

- **Given** 今日が7月5日（7月度: 6月16日〜7月15日 に属する）で、ユーザーが予算タブを暦月期間（7月1日〜7月31日）で表示している
- **When** ユーザーが期間の表示モードをカスタム期間に切り替える
- **Then** 「7月度」（6月16日〜7月15日）のカテゴリ別支出に表示が切り替わり、対象期間（開始日・終了日）が明示される

#### AC-007: 今日が月の後半のとき、切り替えると翌月度が表示される（正常系）

- **Given** 今日が7月20日（8月度: 7月16日〜8月15日 に属する）で、ユーザーが予算タブを暦月期間（7月1日〜7月31日）で表示している
- **When** ユーザーが期間の表示モードをカスタム期間に切り替える
- **Then** 「8月度」（7月16日〜8月15日）のカテゴリ別支出に表示が切り替わり、対象期間（開始日・終了日）が明示される

#### AC-008: 暦月期間の既存表示に影響がない（後方互換）

- **Given** 本機能リリース後のアプリである
- **When** ユーザーが従来どおり暦月期間で予算タブを表示する
- **Then** 従来と同一の集計結果・表示が得られる

### FR-003 に対する受け入れ基準

#### AC-009: 過去の期間に遡れる（正常系）

- **Given** ユーザーが「7月度」のカスタム期間表示をしている
- **When** ユーザーが前の期間へ移動する
- **Then** 「6月度」（5月16日〜6月15日）のカテゴリ別支出が表示される

#### AC-010: 未来の期間へは移動できない（境界条件）

- **Given** ユーザーが今日が属する月度を表示している
- **When** ユーザーが次の期間へ移動しようとする
- **Then** 移動できない（既存カレンダー画面の「当月より先へ進めない」挙動と一貫させる）

#### AC-011: 月の日数差をまたぐ期間移動が正しい（境界条件）

- **Given** ユーザーが「3月度」（2月16日〜3月15日）を表示している
- **When** ユーザーが前後の期間へ移動する
- **Then** 「2月度」（1月16日〜2月15日）・「4月度」（3月16日〜4月15日）が正しく算出される（うるう年の2月を含めて期間の欠落・重複がない）

### FR-004 に対する受け入れ基準

#### AC-012: 共有ノートでも機能する（正常系）

- **Given** ユーザーがペアを組んでおり、ノート選択で共有ノートを選択している
- **When** ユーザーがカスタム期間のカテゴリ別支出を表示する
- **Then** 共有ノートの支出レコード・支出カテゴリに基づいた集計が表示される
